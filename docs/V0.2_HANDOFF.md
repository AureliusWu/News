## Native architecture

`Official RSS -> Miniflux -> worker -> News PostgreSQL -> FastAPI -> Nginx/Vue`

- Ubuntu-24.04 under WSL2 uses systemd; Docker is not required for this route.
- News PostgreSQL 16: port 55432; Miniflux PostgreSQL 16: port 55433.
- FastAPI: loopback port 8000; frontend/reverse proxy: loopback port 8080.
- Miniflux 2.3.3: loopback port 8081; RSSHub: loopback port 1200.
- Optional dedicated SSH server: loopback port 12222.
- SSH reverse forwarding exposes the existing Windows `127.0.0.1:7890` proxy
  only as WSL `127.0.0.1:17890`. Miniflux receives the proxy environment.
- Credentials remain in root-only `/etc/global-news` files. The dedicated
  Windows SSH private key is outside the repository with a restricted ACL.
- PostgreSQL clusters and native runtime data are separate from Docker data.
- RSSHub is healthy as a service, but this accepted source snapshot uses only
  official RSS feeds. No RSSHub feed-route acceptance is claimed.

## Remaining defects and boundaries

### Historical proxy ownership/status defect: closed by September 21 regression

The following paragraphs preserve the September 16 failure evidence. The
September 17 patch and its narrower successful checks are described above.

On PowerShell **7.6.5**, `ConvertFrom-Json` converts the stored ISO timestamp to
`System.DateTime`. `Get-ProxyProcess` compares a freshly formatted timestamp
string to that object. The observed comparison returned false.

The initial SSH process **19584** remained alive and a WSL proxy request still
returned BBC HTTP 200. After a repeated start, the ownership file instead named
**12852**, which was no longer running. `Proxy-Tunnel.ps1 -Action Status`
therefore failed even though the original forward was working. This is a
management-script defect, not missing administrator permission or evidence
that the news services are down.

The original expanded batch was rejected before execution. Its absence of
runtime evidence was subsequently resolved by the isolated-fixture replacement
described in the September 21 closure above: all 16 assertions passed twice.
No process was killed merely by matching a name, and the rejected batch was not
rerun through an alternate execution surface. Unattended reconnection and host
reboot remain separate, unverified operational scenarios.

### Other limits

- One earlier worker restart during feed bootstrap exceeded its 30-second
  stop timeout and systemd killed it. Recovery and data preservation passed;
  graceful shutdown during a slow upstream request remains a follow-up.
- The optional proxy requires the user's existing Windows proxy to remain
  available. No unattended reconnection or Windows-login auto-start is claimed.
- Publisher feeds may contain promotions as well as journalism; WIRED coupon
  entries were observed. This version does not promise editorial filtering.
- The legacy Compose route and earlier version documents are not evidence that
  Docker works on this host. The native route is the locally tested route.
- The GitHub Pages/public backend path, physical-device installation, sustained
  overnight collection, and host-reboot recovery were not tested here.
- Git HEAD, branch and dirty-file inventory were not refreshed in this pass;
  an older handoff's commit must not be presented as a verified current commit.
- No commit, push, release tag, public deployment, or V0.3 feature was added.
