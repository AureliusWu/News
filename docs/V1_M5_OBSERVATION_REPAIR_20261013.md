## 修正方法与完整性证明

- 发现规则保持不变：原门禁仅读取以 `YYYY-MM-DDT` 开头的 JSON。新文件使用原观测时刻的文件名和内容摘要后缀；没有改写 `observed_at`。
- 原始独立观测复制时逐字节校验 SHA-256；从历史数组拆出的记录逐字段核对已有 `compactObservation` 所使用的全部门禁输入。
- 同一 `observed_at` 的副本按内容去重，不增加窗口覆盖数。不允许通过重复点提高成功率。
- 少数 PowerShell 序列化副本省略了 `generated_at` 的小数尾零。例如 `.474970Z` 与 `.47497Z` 表示同一时刻。只在副本比较时识别这种精确等价，优先选择原始云端记录；选中记录的时间文本原样保存，所有不同文本副本另外归档。
- 比较没有按毫秒取整；`.474971Z` 与 `.474970Z` 明确不等价。除小数尾零等价外，任何门禁字段冲突仍拒绝合并。
- 四组文本副本分别用原门禁计算，得到完全相同的判定。没有修改 `freshness-gate.mjs` 或任何阈值。
- 校验最近八天所有合格记录均实际进入 CLI 输出历史；较早的 29 条记录只是按原有八天保留规则不参与当前门禁，仍在完整归档中。
- 原坏点 `2026-10-03T04:31:53.307Z` 完整保留。以其原半小时窗口做独立历史校验，窗口仍失败：`passing_slots=0`、`failed_slots=1`，同窗口后来的好点没有掩盖失败。这是历史规则校验，不是新增生产样本。
