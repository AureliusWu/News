## Known risks and explicit waivers

1. Reliable half-hour publication and seven-day observation coverage are not
   established. The first V1.0.0 report is WARMING_UP with 0/336 closed slots; the
   historical 16/336 calculation belongs to the older 0.9 candidate, not V1.0.0.
2. The unchanged 3,000 ms performance budget is not met. The corrected frozen-
   input CI diagnostic had desktop median/worst 913.336/915.199 ms and mobile
   median/worst 3717.132/3721.044 ms. It excludes third-party HTTPS resources and
   uses loopback delivery; it does not establish public/mobile interaction SLA.
3. Physical-phone evidence remains unavailable; 390px browser emulation is not
   relabeled as a real device.
4. The complete historical-client, installed-PWA and cross-browser offline matrix
   remains incomplete despite the exact Chrome upgrade case passing.
5. The previously blocked Windows full start/stop and fault-injection acceptance
   remains unexecuted. Linux CI is not substituted as Windows proof.

Additional compatibility observations: the in-app browser had one event-link
click that did not change route, while the same navigation cases passed in Chrome
and Firefox CI. Direct public event navigation rendered correctly with no captured
console errors. GitHub Pages can return HTTP 404 for a deep URL while serving the
verified SPA shell; the live browser rendered that detail. These are disclosed,
not silently labeled universal compatibility passes.

Original failed runs are preserved, including the source-health schema mistake,
bundled Chromium sandbox failure, mislabeled Lighthouse desktop cohort and mixed
Python dependency conflict. Their fixes do not remove the original records.

## Operation and rollback

The public site uses static snapshots, not a hosted native API. Docker and
Cloudflare are not prerequisites for visiting it; Cloudflare remains deferred.
The collector's `0.4.0-alpha.1` producer identifier is separate from app V1.0.0.

If an existing tab still shows 0.9, use the site's page-update/local-bookmarks
section and its check-for-update control. Do not clear browser data merely to
update: bookmarks are local and clearing storage can delete them.

The previous exact app/data Pages artifact from run `38702292514` was backed up.
While its Actions artifact is available, `restore-pages.yml` accepts
`source_run_id=38702292514` for a paired rollback without recollecting or rewriting
timestamps. Attached archives preserve original bytes for later manual recovery.
No production rollback was performed as part of this release.
